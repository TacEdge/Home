# ADR 0006 — M3 manual family data + capture: scope, gate and decisions

Status: **Accepted**, 2026-10-04 (owner approved the M3 plan, decisions 1–5 and the settled items). Contract: `docs/m3/M3-BUILD-CONTRACT.md`.

## Context

M2 is complete (ADR 0005, closed by PR #29). M1 is deployed to production but not accepted: Postmark live sending, signed-in production checks, live rate-limit verification and the Neon recovery condition remain open (`docs/runbooks/DEPLOY.md` §E). ADR 0005 §1 gated "M3 real-user and real-data work" on those items. The owner wants M3 to make HOME visibly usable, and has clarified that the gate applies to real household data in Production, not to development on synthetic data.

## Decisions

1. **M3 development proceeds now; real data stays gated.** M3 is built and tested on synthetic data in local and Preview. Real household data enters Production only when the real-data gate opens (§2). This refines ADR 0005 §1 (D-M2-1): the gate is on *real data*, not on building M3.
2. **Production real-data gate (owner decision 1).** In Production every family-domain write is refused unless `HOME_REAL_DATA` is exactly `open`; missing, blank, malformed or any other value keeps it closed (fail-closed). Authentication, auth audit, Activity, boot guards and other infrastructure stay operational, and an unexpected value never fails boot. The gate does not apply outside Production, so local and Preview development continues. The owner sets the value only after every DEPLOY.md §E item, the M3 restore rehearsal and the export check are recorded. Contract §6.
3. **Recurrence in M3 (owner decision 2).** A limited model, built by the `recurrence` engine with the `rrule` dependency: none, daily, weekly on chosen days, fortnightly, monthly on the same date, yearly; ends never, on a date or after N times; whole-series editing; **skip this one** via exdate. Single-occurrence edits, imported-calendar recurrence and richer exception handling (RECURRENCE-ID overrides, feed EXDATEs) stay in M4, which extends this engine. Regular-week derivation stays in M4 (ADR 0005 §4). This moves the recurrence engine's first version from the M4 roadmap line into M3. Contract §5.
4. **Plain Forward in M3 (owner decision 3).** `/forward` is a factual 30-day agenda grouped by day. No conflict, coordination or Week Ahead intelligence is brought forward from M6.
5. **Accessible Mist (owner decision 4).** Amends ADR 0004. Mist as specified (`#8C9C95` day, `#7F8D88` night) is about 2.6:1 on Morning and 2.3:1 on Linen by day, and 4.3:1 on Linen at night, below WCAG AA (4.5:1) for the small labels and times the brand assigns it. Text uses an accessible Mist: **`#5A6B64` by day** (5.1:1 on Morning, 4.6:1 on Linen) and **`#8E9B96` at night** (5.9:1 on night ground, 5.1:1 on night Linen). The original Mist is kept for decorative, non-text marks only (hairline accents, load dots that are never the only signal). In code, `--muted` becomes the accessible text value and a new `--muted-mark` holds the original; Package 1 makes the change with a contrast unit test. `docs/BRAND.md` records the mapping.
6. **Export (settled).** Each adult exports their own authorised view as versioned JSON (`home-export`, version 1): household records, their own private records, captures, proposals, conversations, insight responses and their own Activity. The other adult's private records never appear. Sensitive context is included only when the person explicitly ticks **Include sensitive items**, through the audited sensitive read. No import in M3. A completeness guard fails when a column is neither exported nor deliberately excluded. Contract §7.1.
7. **Recovery before real data (owner decision 5).** Neon point-in-time restore with ≥ 7 days on `home`, plus a successful, dated restore rehearsal (end to end on `home-dev`; branch restore and verification on `home`), plus the versioned JSON export, is sufficient before real family data. No scheduled dump in M3. Contract §7.2.
8. **Purge deferred (owner decision 5).** Automated purge execution (30-day archived and dismissed captures, 90-day conversations) is deferred; real data may enter before it exists. Until it does, UI and copy must never imply that archived or dismissed records have been permanently deleted. The retention model of ADR 0005 §6 and §43 is unchanged.
9. **No schema changes planned.** M2's schema holds everything M3 uses: `rrule` and `exdates`, `origin_capture_id`, capture statuses, context sensitivity and status, `person.user_id`, the P-1 audit columns. The gate is an environment variable; export and restore need no tables. A migration found necessary later is a contract amendment and follows migration-first (ADR 0005 §16).
10. **Full pages now, sheets later (settled).** Every detail has its own URL; M3 renders full pages. The concept's sheets are layered over the same URLs later (M5/M6) without changing routes.
11. **Notes live on a subject; manual organisation through the executor; capture wording (settled).** The M3 UI creates notes only on a project, person or event; a free-floating thought is a capture. Organising a capture by hand creates a proposal as the person and approves it in one transaction, so the existing executor and capture settlement run unchanged and provenance is `ui` (ADR 0005 §43); no second organising path exists. The capture bar reads "Tell HOME something…" until Kev arrives in M8.
12. **Kev transcript and usage recording moves to M8 (settled).** The open question in ADR 0005 §39 (how Kev's orchestrator records its own transcript and usage) is decided with the orchestrator in M8, not before M3. M3 adds no Kev write.
13. **Packages are acceptance boundaries (owner rule).** A work package may be split into smaller PRs when its size warrants, without changing its approved architecture or scope. Every PR is owner-merged.
14. **Fixture seeding stays local only (settled).** `home-dev` and Production are never seeded; Preview data is synthetic and entered through the UI.
15. **Implementers.** Opus for Packages 0, 1, 2, 4, 7 and 10; Fable for 3, 5, 6, 8 and 9; Opus reviews every Fable PR before the owner merges.

## Consequences

- ROADMAP: M2 complete; M3 in progress on synthetic data, real data gated; M4 extends M3's recurrence engine.
- DEPLOY.md §E gains the M3 gate items (restore rehearsal, export check, logging review, opening the gate). The env table gains `HOME_REAL_DATA` in Package 1.
- ADR 0004 and `docs/BRAND.md` are amended for Mist (§5).
- ADR 0003 §8 ("revisit logging before real data") becomes an explicit gate item: before opening the gate, the owner confirms runtime logs carry no family data and decides whether error tracking is needed (default: no).
- M2-ACCEPTANCE records M2 as accepted; its open items move here or to DEPLOY.md §E.
